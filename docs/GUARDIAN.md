# Guardian 本地电脑卫士

Guardian 是 Company、Messages、Plan 之外的第四个主视图，采用浅色商业界面：浅灰工作区、白色数据面板、蓝绿色图表与明亮的交互地球。界面与现有视图共用 Aexus 的认证 Core API，系统采样位于 Node Core，渲染端只负责展示与交互。

## 本地复原

本地源代码从 `25d686ee706b62592ef170c189df2a62602e2b6a`（0.58.1，引入 domain Engine 工作区之前）恢复，保留频道、群组、员工、Company、Messages、Plan。之后的 domain Engine 启动库、作用域和研究工作区不再属于当前应用。原本用于员工运行的 Codex / Claude / Cline / Pi 适配器保留，供既有协作功能使用。当前版本为 Aexus 0.66.1；macOS 本地候选构建与安装不代表公共软件包的再分发许可已经完成审核。

## 真实采样与范围

- CPU：相邻系统计数的差值，首个采样尚无百分比；进程 CPU 为系统进程工具返回的口径，多核进程可以超过 100%。
- 内存：物理内存、活动/非活动、压缩、固定内存与交换区；不同口径不冒充 macOS 活动监视器的完全相同数值。
- 磁盘：用户数据所在卷的实际可用与已用容量，避免用只读系统卷误报整机使用率。
- 网络：可见 TCP 连接、监听端口、进程与本地/远端地址，以及各接口的累计字节和采样速率。物理接口与隧道接口不会相加重复计数。
- 安全配置：读取系统防火墙、FileVault、SIP 状态；读取失败时显示未知。Guardian 不会更改这些配置。

连接不等于攻击。内核 TCP 表不能证明每个请求的发起者、HTTP 内容或恶意意图；只有能与监听端口匹配的连接才提供入站线索，其余方向显示未知。短暂连接、UDP/QUIC、未建立连接的探测、所有包级攻击不在该采样视野内。防火墙状态也不是无攻击的保证。

## 地球与地址授权

地球海岸线使用本地打包的 Natural Earth 公有领域地图，不加载外部地图。旋转、缩放、点选和连接弧线都在本机渲染；图上只绘制已观测且定位成功的公网端点。

公网 IP 查询默认关闭，用户可在 Guardian 的位置设置中明确启用或关闭。启用后使用 HTTPS 请求 `ipwho.is`；仅发送需要定位的公网 IP，不发送进程名、PID、端口或私有 IP。手动填写经纬度可指定地球锚点。IP 地理位置通常是大致城市或地区，公网出口也可能是代理/VPN，不能用来推断精确物理位置或人员身份。

## 变化与安全运营（按需 / 用户授权后台采样）

Guardian 已在原有数据仪表盘之外加入应用档案、事件调查、AI 行为可见性以及最近七天摘要。

- **应用档案**：按进程名聚合当前 PID、CPU、RSS、TCP 连接及公网对端；进程名不能代替软件签名、安装包身份或权限使用证据。趋势只从应用页面打开后开始积累，不回填。
- **事件调查**：仅比较当前 Core 进程中时间相邻、成功返回的采样，识别 CPU 负载由低至高、内存压力恶化、已知保护配置变化以及已观察过的进程新增公网 TCP 对端。缺失网络 / 进程采样不触发对端变化；一条连接并不能证明恶意行为、上传内容或首次联网。首次采样只建立基线。
- **用户确认与复核**：事件详情显示对象、首次/最近时间、观测记录、人工备注。状态区分待核对、人工已核对、已忽略；用户还可以主动进行最多 8 次真实复核采样，对照整机 CPU、内存压力、已确认的关联 PID、TCP 对端和保护状态。对照仅证明采样时的值，不会判定任何动作导致性能改善；“已核对”不等于完成整改或降低风险。
- **团队委派**：用户在事件详情中明确选择就绪员工，确认后通过既有 `session.send` 向其发送原始事件信息，后者可能包含公网 IP 并触发外部 AI 服务。未确认时无派发，不在新视图中自动执行系统操作；相关请求保留在 Messages，发送后的回执不是整改完成证明。
- **AI 行为**：列出 Core 中已有员工、活动会话、可见任务元数据、待批准动作和当前工作目录。尚无逐文件更改归属、实际费用、外部请求逐条追踪或统一自主性策略。
- **七日回顾**：按留存事件及人工状态汇总最近七个日历日；复制的脱敏文本只包含聚合数量、类型、覆盖提醒，不含事件标题、进程、路径、主机名、IP 和备注，当前无自动周报通知。

**事件保存**：记录保存在应用主目录 `guardian-events.json`，写入临时文件后原子替换，文件权限 `0600`。仅保留最近 7 天、最多 250 个事件、每项最多 24 条时间线记录；包含观测进程名称、PID 和公网对端 IP，请按敏感本机数据对待。默认只在 Guardian 页面请求采样时识别变化。用户可在「位置与隐私」中独立启用后台只读采样，启用后仅在 Core 运行时每 60 秒读取一次相同的系统快照，不会调用 Agent 或自动处置；关闭立即取消后续定时采样。即使启用了后台模式，短暂 TCP 连接、软件退出和设备休眠/关机时段仍无法补齐，Core 重启后的第一份快照重新建立基线。若外部 IP 定位也已单独授权，后台采样同样可能向 ipwho.is 发起 IP 查询。

**Core API**：`guardian.event-list` 只读，用户与被授权的高级角色可读取事件；`guardian.event-create` / `guardian.event-change` / `guardian.event-note` / `guardian.event-sample` 仅人类用户可用，Agent 无权自行伪造/关闭事件。事件写入错误列为快照观测缺口，不能阻断 CPU 等原有只读监控。

未来阶段仍需实现更细粒度、可可靠断点恢复的后台巡检、可信行动验证、OS 级应用权限采样、GPU、AI 文件操作归属和多设备历史同步。目前仅用户明确授权后才派发既有员工，不提供自动封禁或无授权处置。
