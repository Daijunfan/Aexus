# Anexus 0.56.0

项目正式使用 Anexus 品牌，沿用原来的图标。Anexus 将已有 Coding Agent 放进可以相互协作的工作环境：可以做开发、处理日常事务、阅读研究，也可以按用户自己设定的规则做角色互动、工作或社会实验。开放生态和 CLI 优先是底层设计；普通用户可以从对话和 Secretary 开始使用。

## 使用变化

- 群组及频道发言显示实际作者的头像。用户可以上传自己的照片、选择现有形象、预览、保存或重置；发言角色按真实员工 ID 显示头像，已删除角色保留明确的替代标识。
- All Conversations 中，同一个 Telegram 频道不再因频道与唯一来源同时入列而重复。保留频道讨论入口、来源分类和聚合频道的实际区别。
- All types 使用项目自己的下拉控件，跟随主题与键盘交互。Category 可横向滚动，隐藏滚动条。
- 文件树、资产列表和工作区内的文件/目录都能找到 Open in Finder 操作。Core 先检查作用范围和路径；远端、纯云端和浏览器场景给出真实限制及已有下载/复制路径，不把服务器路径当成本机路径。
- 文件工具右侧边缘可拖动，支持键盘调整，宽度持久保存，并与聊天及工作区覆盖层同步。

## 品牌和兼容

应用、登录页、设置、README、桌面包和源代码包使用 Anexus 名称，macOS 安装为 Anexus.app。保留图标、bundle ID、用户数据目录、工作区绑定、员工身份和既有协议。新增 anexus CLI 别名，原 agents 命令继续工作；相同操作连接同一 Core。

安装器可以从 Agents Company.app 正常升级到 Anexus.app，检查旧进程，保留现有数据和升级恢复路径。没有因为品牌改名重新创建员工或迁移真实用户文档。

## 宣传素材

本轮重新制作至少20篇、多图小红书帖子，每篇一个独立文件夹，最多8张图。多数帖子面向普通用户，围绕一句话交给Secretary、助手分工、角色互动、资料阅读、待办和计划等真实场景；少数独立篇目面向开发者，说明CLI和多引擎生态。

宣传图片以当前应用界面为基础，每张保留可读 GitHub 链接。工作场景使用独立测试环境中的真实 Claude Code、Cline 和 Pi 调用，以及 Linux、Windows 远端工作目录；引擎运行在 Core 主机，经 SSH/Tunnel 操作远端文件，不将其描述为远端原生引擎。纯界面操作示例单独标注，不伪造模型回复或任务完成状态。Codex 本轮连接失败会在验收记录中保留，不计入成功的真实执行。旧图片经最终检查后删除并替换，制作源文件和验收记录保存在本地 artifacts 中。

## 验证边界

功能验证使用临时Core/工作区、确定性协议、无头浏览器和隐藏macOS窗口。真实Finder调用路径通过原生回调验证，避免验收时弹出系统窗口。Windows和Linux原生桌面不能由Mac结果推断通过。详细结果保留在本地发布验收报告中。

## 本机发布验收

- 完整 Core 回归：85 项通过；本次改名后，类型检查、构建、CLI 契约、Secretary API 覆盖、隐藏桌面文件操作及安装器检查通过。
- 实际 macOS arm64 安装包与安装后的 `/Applications/Anexus.app` 均在临时数据目录、隐藏窗口中启动检查通过，版本为 0.56.0。核验了 Anexus 标识、个人头像入口、文件侧栏、三个视图、文档 API 和随包插件。
