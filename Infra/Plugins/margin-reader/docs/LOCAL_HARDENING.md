# Margin Reader：大文库、正文词典与交互时序加固

## 范围与结论

本轮从已有源码基线继续开发，只改 `PlugIns/margin-reader/`。现有单击回源、原文取消标注、脑图、手写、复习、媒体和导出实现均保留。未替换运行中的 Agents Company，未修改宿主，未调用真实模型。

本报告与 [DEEP_AUDIT.md](DEEP_AUDIT.md)、[MARGINNOTE_COVERAGE.md](MARGINNOTE_COVERAGE.md) 一起构成功能、性能、交互、数据可靠性和互操作的审计。前一份报告保留 228 命令阶段的性能对比；本轮扩展至 231 个公开命令。命令数量不能换算成 MarginNote 功能完成率。

官方依据：MarginNote 4 手册的[个人字典](https://manual.marginnote.com.cn/mn4/card-links-keyword-title-links-build/)、[备份与恢复](https://manual.marginnote.com.cn/mn4/data-sync-backup-restore/)、[同机多窗口](https://manual.marginnote.com.cn/mn4/multi-window-linking-opening-multiple-mn4/)。手册将同名词条候选、子脑图字典、正文词条和完整本地备份列为具体操作路径，因此仅有卡片内搜索或小型 ZIP 导出不足以覆盖这些需求。

## 一、这轮关闭的具体缺口

### 1. 大文件可以导入，整库却不能备份

旧实现把所有数据读入内存 ZIP，整库原始数据限制 256 MiB。此限额小于单个文档允许的导入大小。现在保留旧格式，同时增加可选 `format:segmented`；界面默认使用分块格式。

新格式是 `.mrbackup` 目录包。数据按 4 MiB 分块，块和整文件均校验 SHA-256。加密包使用 scrypt 与 AES-256-GCM，清单和内容加密，磁盘块名使用带密钥摘要；不同备份间直接替换密文会被拒绝。迁移必须复制整个文件夹。

`library.backup.plan` 在写入前报告文件数、内容大小、最大文件、预计新增空间及实际可用空间。创建结束前校验元数据版本、目录清单和文件版本。并发修改会返回冲突，不发布混合快照。恢复先在私有暂存目录写入，校验成功后才发布到一个新目录；不会覆盖用户已有空目录。

回归覆盖：错误口令、缺块、截断、内容损坏、跨包密文替换、路径穿越、Unicode/大小写路径冲突、文件被用作父目录、软硬链接、写满磁盘、恢复时目标被抢先创建，以及复制期间文件和 API 状态被修改。小型真实 PDF 学习集同时验证 ID、摘录 PNG、原件、空目录、版本与回收站的恢复。

容量预算是 1 TiB / 100000 个文件 / 128 层目录，状态和清单各限 64 MiB，并受结构校验预算限制。实测容量另列，不能把配置上限算作已测试规模。尚无中途续传；真实断电、长时间运行和外置盘热拔插不在本轮证据内。硬退出可能留下 `.margin-reader/backup-staging/` 私有暂存，不能当成完成的备份。

### 2. 标题词典只在卡片中工作，正文阅读没有入口

新增 `study.dictionary.match` 和 `study.dictionary.lookup`。匹配在 Core 完成，界面只绘制返回的范围并调用公共接口。支持标题、标签、英文/中文分号别名、最长词优先、大小写和拉丁词边界。Unicode 大小写变化和 emoji 不改变原文 UTF-16 定位。

PDF 使用其原生文字层，流式文档使用原始文本节点；下划线是独立图层，不重新包裹或拆分文字节点。单击词条可阅读 Markdown、公式、图片和评论；同名词条先选择候选。查阅和编辑保持当前原文位置，明确选择打开才跳转。代码、已有超链接等区域不抢占原有交互；原文已有标注的编辑菜单优先。

新增子脑图字典来源。可选择同工作区其它学习集、主脑图及全部后代或特定子脑图，并选择四种来源颜色；重叠配置以更具体的子脑图为先。跨学习集剪切后，字典继续解析稳定身份。自有学习包导出包含字典依赖，导入时重映射来源 ID。

不隐藏超量数据：每次匹配最多输入 262144 个 UTF-16 单元，结果按最多 200 处分页；每处先返回 20 个候选及总数，候选查询可以继续分页。界面密集正文显示一组后提供「后续词条」。这属于明确的呈现预算；来源数据和完整检索结果仍可读取。

### 3. 新增异步图层与初次适配的竞态

首轮完整回归未直接通过。PDF 版式测试在仍处于 `aria-busy=true` 的初次重排期间使用上一帧坐标开始拖选，现场记录显示页宽从 439 变为 419，选区锚点落到错误位置。图片手写测试则在撤销返回后、图像重新挂载前读取边界，得到空值。

产品处理：原文内容处于未就绪的重排阶段时，不接收新的选区/笔画手势；已就绪 PDF 页面不会仅因后台元数据刷新而被禁用。开始书写后维持已有的延后重排机制。词典的后台结果不能在鼠标仍按下或原文选区仍存在时重绘图层。没有命中的页面不创建空字典层。

测试处理：版式测试等待可观察的页面几何稳定再记录指针位置；图片像素检查等待截图中的真实图像可见后读取边界。另一次原文菜单回归在改色 API 已保存、标注层尚未重挂载时读取到了空边界，现改为等待原文标注实际显示新颜色及就绪几何，再使用真实鼠标点选；没有以 API 返回代替界面完成。原先的源坐标范围、彩色像素位置、擦除、撤销、套索和原件哈希断言全部保留。新增延迟词典响应测试：按住真实鼠标拖选时放行响应，确认没有中途重绘，最终保存的摘录文字与真实选区一致。

### 4. 输入发生时间与处理时间分离

一次全量运行中，1061 页原始 PDF 的惯性翻页断言收到第 102 页而非第 101 页。单次复跑虽然通过，仍保留该失败。检查发现手势静默间隔按 `performance.now()` 的处理时刻计算；忙碌渲染可能把属于同一输入时间线的事件分成两段。

现在优先使用 WheelEvent 原始时间戳，未知或旧 epoch 时钟才回退，并防止乱序事件使时钟倒退。新增确定性用例：输入发生间隔 25 ms、处理延迟每次增加 450 ms，横向和整页纵向各只翻一页，后续独立反向手势正常工作。浏览器手势测试使用 Chrome DevTools 的原生输入接口保留原始 25 ms 时间戳，继续校验实际第 101 页、反向第 100 页和原件哈希；其它普通滚轮和速度检查仍走真实浏览器滚轮。该模拟不能替代实体触控板的所有惯性曲线与平台手势阶段。

### 5. 受保护元数据的大小写别名绕过

在独立临时文库复现：旧构建接受 `fs.list {path:".MARGIN-READER"}` 并返回私有缓存、回收站和上传目录。原来的保留名称判断区分大小写，在当前 Mac 文件系统中并不能隔离同一目录的别名。原始探测记录保存在 `metadata-alias-before.json`，没有访问真实用户元数据。

修复后，路径检查和递归目录操作统一保护大小写、Unicode 兼容写法、尾随点/空格及元数据流别名；公开列表隐藏这些名称，复制、移动、上传和回收站操作不能借此绕过保护。旧版与分块备份共用相同的清单规则，实际非标准大小写的员工/Git 目录不会进入备份。文件观察器也识别大小写变体，避免重新引入通信事件循环。

新增拒绝路径、递归操作、两种备份及监听器回归，并把大小写别名拒绝加入真实员工启动器测试。此结论只覆盖插件公开 API；它不把受信任的 Node 插件变成隔离整个系统的安全沙箱，也不声称已经在 Windows 硬盘上验收。

### 6. 过期响应覆盖新导航、原文菜单被程序滚动关掉

继续回归暴露出返回学习集后又被旧阅读渲染隐藏的时序问题。根因是旧 `renderer.show` 或事件刷新在 `await` 返回后仍应用结果，未检查用户已完成新导航。现在这些阶段携带导航代次，过期结果不再恢复旧文档；渲染完成回调也确认当前确有文档，才切到阅读界面。

原文标注菜单此前在任意 scroll 事件时关闭，程序性的适配和联动也可能让菜单在点击“取消标注”前消失。现在程序滚动保留菜单，真实滚轮、外部点击和 Escape 仍关闭。新增确定性测试主动挂起正文请求和旧设置响应，等用户已返回主页后再放行，确认新导航不被覆盖；再让已打开的标注菜单经历程序滚动，使用真实鼠标完成取消标注。涂抹删除测试在读者窗口初次排版稳定后记录手势坐标，保留按住即删除、松开不重复写和撤销还原的检查。

工具栏已继承前轮的分组和响应式布局；此次词典菜单沿用现有对话框，字典下划线支持键盘。单张截图只能证明当前尺寸的可见效果，不能证明全套商业软件的视觉细节、触摸可达性或辅助技术覆盖。

## 三、性能解释

前轮已解决万张卡片全量 DOM 的明显阻塞。本轮重新测量同一 10000 张文字卡、200 分支数据，并增加词典匹配/候选查询耗时。大备份测试另用超过 1 GiB 的实际文件内容，读取和恢复均校验哈希；这两类工作负载不能互相代替。

元数据仍为共享 JSON 状态。写入、历史快照和复杂操作的成本会随总元数据增长；视口渲染只降低浏览器 DOM 成本。分块备份限制的是原始文件数据的驻留窗口，恢复时仍要验证状态与解析缓存；不能把二进制大文件工作负载的内存结果外推到上千份富文本缓存。没有证据表明十万卡片、巨量手写、千份大 PDF 同时处理也有相同延迟。性能数字只描述本插件在这台测试机上的结果，未运行 MarginNote 商业软件基准，因此没有“性能超越 MarginNote”的结论。

环境为本机 Apple M5 Pro / macOS arm64 / Node v26.5.0 / 已安装 Chromium。三个独立临时文库各含 10000 张文字卡、200 个分支，状态约 5.83 MB。数字不是 MarginNote 对比，也不是大图、多笔迹或长时间驻留的结果。

| 首次界面就绪（ms） | 238.71 | 231.69 | 238.96 | 238.71 |
| 切换卡片盒（ms） | 135.76 | 306.59 | 345.45 | 306.59 |
