# 0.9.4：节点拖放与资料封面收尾

本轮继续已有0.9.2／0.9.3实现，修改范围只在Margin Reader。原文、主题身份和父子关系通过同一公开Core维护；不重新创建另一套导图数据。

## 确定的手势

从主题A按住左键并移动到主题B的主体内，松开后B成为A的父主题，A的后代完整跟随。目标主体的上沿、中部与下沿都执行相同的父子操作；同级排序只使用主题外部的插入区域。绿色轮廓与指针旁文字给出明确结果。折叠的目标在同一个操作中展开，撤销同时恢复原层级和折叠状态。

普通移动、选择和显式父子关系工具现在共用整支预览、目标命中、撤销和取消流程。总览合批图形仍是可操作主题，不会因为没有挂载完整HTML元素就退化为拖动画布。空白处或明确中键拖动平移画布；主题拖动保持原缩放和非选中分支的位置。

拖出脑图区、拖到相邻文档或浮层上再松开，会取消本次移动，不改写顺序、父主题或原文。按住不放再返回目标主题可以继续完成操作。Escape、指针取消和失焦仍取消，外部修改触发版本冲突后不会自动重试覆盖。

重叠布局中，拖动主题已经离开的旧矩形不再挡住下面的有效目标；没有有效外部目标时，拖入自身或后代仍被拒绝。直接拖入目标主体优先执行明确连接，Alt表示显式自由摆放。

## 资料封面

收尾交付保留完整PDF封面和HTML页面预览，按原比例显示，不裁成顶部横条。资料项为紧凑书架，标题两行，格式、大小、页数与文件夹分层显示，不再留大块空白。移除关联入口悬停／键盘聚焦时显示；触摸界面常显，仍需确认并保留原件。无预览格式有纸张占位，文件缺失和更新状态单独显示。

预览继续使用document.preview与原有懒加载、缓存和权限约束。网格、列表、深色、窄窗口和左右并排共用组件。完整回归还发现新增按钮使最窄的并排脑图区挤出“更多”入口；现在按分栏宽度分两级收纳工具，原来的格式和删除操作保留在可点击的更多菜单中。

## 官方交互依据

XMind《Topic Editing》描述通过拖放重组主题层级，整支主题可以一起调整，常用Enter／Tab和撤销路径用于编辑：https://xmind.com/user-guide/topic-editing-new

MarginNote 4《移动、合并、重组》明确说明A拖到B、出现绿色成为子卡片提示后，A和其后代移到B下：https://manual.marginnote.com.cn/mn4/mind-map-cards-move-merge-regroup/

XMind自由主题参照：https://xmind.com/user-guide/floating-topic 。本插件针对明确落入主体的行为按用户要求进行连接，Alt保留独立摆放。没有采用拖到相同目标就自动合并文本的行为。

既有54套自主骨架、混合拓扑、关系线、外框、概要、可编辑内容与MarginNote式准确回源继续共用原节点。参照官方可观察行为不表示逐像素复制商业客户端，也不代表全部商业私有格式兼容。

## 验证与保留的失败记录

接续时的基线：封面、普通拖放、总览拖放通过；旧自由主题测试仍把落入中心当作不连接，和新用户语义相反。修订后同时验证直接连接、一次撤销精确还原，以及Alt自由摆放，未删除其后的宽度、折叠动画与重开检查。

另先复现了两个真实缺陷：拖出画布仍改变顺序；旧移动矩形遮挡重叠目标。失败日志、修复后的纯函数/Core测试、浏览器与原生鼠标测试均留在本轮artifacts中。

`npm run test:topic-covers` 包含封面、完整子树、总览与越界取消。`npm run test:deep-audit` 运行当前产品全部回归。`npm run test:agent-acceptance` 独立验证构建、Core、宿主、正式员工启动器、主页新建团队及隐藏原生界面。最终结果以该版本固定构建的日志、结果JSON和安装哈希为准。

所有测试使用隔离临时数据。实际文库验证只操作临时副本，并比对真实原件与状态未被测试改写。实体触控板、实体笔、其他操作系统和长时间重媒体压力不由本机自动化事件结果替代。
