02执行、检查、修订、交接

PROCESS DETAIL
  1. 03
    阅读阶段交流

    在 Messages 查看任务正文、阶段说明和问题。公开作者与员工原生输出各自保留身份。

    交付检查 · 任务的交流记录
  2. 04
    回查执行记录

    在 Plan 查当前规则、任务状态和保留历史，区分等待、运行、暂停与实际执行尝试。

    交付检查 · 发生过的工作线索
  3. 05
    打开实际产物

    检查代码、文档或其他文件，与原定验收点对照；完成回复和调度状态不代替业务检查。

    交付检查 · 可打开的具体成果
  4. 06
    安排明确修订

    把发现的问题、触发方式和材料交回负责人，保留修订结果，再决定是否继续后续工作。

    交付检查 · 连续的修订与复核

03触发与处理的基本规则

CONTROL RULES
  • 工作状态、运行记录与业务结果是不同信息，应该结合起来检查。
  • 计划完成意味着没有剩余计划次数，不自动认证任务产物完全正确。
  • 查询与阅读状态不会替代真实执行，实际结果需要由文件与行为支撑。

04需要看清的输入范围

INPUT CONTEXT

任务示例：让员工完成一次资料或开发任务，明确要求文件、过程说明与待核对事项。Company 看状态，Messages 看讨论，Plan 看实际记录，最后打开产物检查而不只听一句完成。
