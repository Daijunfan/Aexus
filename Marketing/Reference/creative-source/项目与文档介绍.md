# Avalon：把 Coding Agent 组织成能协作的工作空间

Avalon 是一个开源工作台。它在 Codex、Claude Code、Cline 和 Pi 等编码引擎之外，提供员工身份、Team、消息、文件、任务与插件能力。你可以从界面开始，也可以让员工通过公开 CLI / Core API 操作。

## 三个视图为什么放在一起

Company 负责看组织：团队、员工、工作状态与协作关系。Messages 负责看交流：私聊、群组、频道、原文资料与员工讨论。Plan 负责看节奏：一次、重复和事件触发的员工工作。三种视图沿用同一身份与工作空间，让“谁来做、怎样沟通、何时继续”接在一起。

## 秘书怎样降低使用门槛

由用户创建 Secretary 角色，先完成引擎和模型服务准备，再把一个具体目标告诉秘书。它可以在当前授权范围内协助管理团队、员工、频道、计划与插件；具体执行由合适员工承担。用户仍决定目标、必要授权和 Secretary 任免。

## 群组的关键是共同背景

群消息送达全部当前成员。艾特和回复决定谁处理这一步，其他成员同步知悉上下文。成员看到讨论，不等于每个人都必须公开发言。公开发言保留真实作者，实际文件承接下一次交接。

## 频道与自动化可以怎样配合

配置 Telegram、X、YouTube 等来源后，频道可以承接原始内容。让有资格的员工参与频道，再交代一次解读任务或配置新帖事件任务。原文与解读互相连接，用户可以继续追问和核对资料。Plan 的事件任务与定时、重复任务共用管理入口；Core 与采集服务需按工作流保持运行。

## 多引擎、多主机的边界

员工引擎在创建时确定，模型服务商另行配置。Codex / Claude Code 具有已适配的远端原生路径；Cline / Pi 可以通过 Tunnel 使用远端工作区，当前不提供云端原生进程。主要部署方式为 Mac 与 Windows 桌面，以及 Linux Core / Web 后端。Team 绑定真实主机与目录，按实际能力选择执行方式。

## 本套文档和海报怎么读

每篇六张：第 1 张用流程图建立全局，第 2 张解释问题与机制，第 3 张用分工与 DFD 说明材料流向，第 4 张说明处理与下一步，第 5 张给出可改写的任务交代，第 6 张引导开始一个小任务并收藏项目。

流程图中的椭圆表示起止，矩形表示处理，平行四边形表示输入输出，菱形表示判断。DFD 中矩形表示外部实体，圆形表示处理过程，两条平行线表示数据存储。所有连线由 Graphviz 布局，保留 SVG 与 .dot 源文件。
