02收到任务后怎样推进

WORK ORDER
  1. 01
    打开项目文档

    访问 GitHub 上的 Avalon，阅读 README 的环境、启动、引擎与部署说明，选择与你的平台相符的入口。

    交付检查 · 真实的起步路径
  2. 02
    准备运行环境

    使用桌面版或按源码步骤准备依赖、插件和应用。Linux 主要使用 Core / Web，按实际方式连接。

    交付检查 · 可访问的 Core 与界面
  3. 03
    配置引擎服务

    选择需要的编码引擎与模型服务，检查程序、协议和认证；安装程序不自动提供账号或推理额度。

    交付检查 · 准备好的执行入口
  4. 04
    创建秘书身份

    由用户任命 Secretary，告诉它材料在哪、想拿到什么、需要几个职责，先从一个小任务开始。

    交付检查 · 清楚的组织与工作目标
  5. 05
    查看三个视图

    Company 看成员与关系，Messages 看群组与讨论，Plan 看保存的任务和下一步安排。

    交付检查 · 连续的过程观察
  6. 06
    检查第一份产物

    打开实际文件并对照目标；补充修改后，按需要增加员工、插件、远端主机或重复任务。

    交付检查 · 验证过的第一条工作路径
