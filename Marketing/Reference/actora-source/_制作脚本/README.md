# 可复现制作流程

全部 Electron 窗口隐藏，业务数据位于临时目录。捕捉脚本必须顺序运行。没有使用 AI 图像生成，没有修改真实用户笔记、员工或主机。

```bash
node 宣传素材_小红书_2026-09-26/_制作脚本/capture.mjs
node 宣传素材_小红书_2026-09-26/_制作脚本/capture-hierarchy.mjs
node 宣传素材_小红书_2026-09-26/_制作脚本/capture-notion-icons.mjs
node 宣传素材_小红书_2026-09-26/_制作脚本/render.mjs
python3 宣传素材_小红书_2026-09-26/_制作脚本/package.py
```

- `capture.mjs`：十篇不同功能场景；真实 UI、公开 CLI、隔离示例数据。
- `capture-hierarchy.mjs`：0.44.1 的中央 Governor、四个方形 Team、3/4/5/3 位 Employee。17 位工作、3 位休息，一条绿色交互。三类员工：4 位云端原生、5 位本地运行操作云端、6 位纯本地；Manager/Governor 始终是 Mac 本地运行与本地工作区。所有人物由真实的角色身份调用 CLI 创建与摆放。
- 模型响应与 SSH 传输由本地 fixture 提供，不联系实际云主机，不产生模型账单。原生云端进程适配器也只连接协议 fixture；本次画面不作为真实远程执行证明。
- 所有跨 Team 连线、侧边端口、工牌箭头、团队内主干与绿色活动状态均由实际 App 渲染。海报不添加示意连接。
- `capture-notion-icons.mjs`：验证已有图标/封面 API、界面修改及关闭重开持久化，用真实窄窗口布局拍摄六卡片封面。
- `层级截图与验证.json`：角色、创建来源、工作环境、API 操作、活动、路由与几何证据。
- `campaign.mjs`：十篇文案与每张独立的展示目的。`render.mjs` 输出三十张 1440 × 1920 图片与预览；`package.py` 校验数量、尺寸、哈希并重建 ZIP。
- 每张原始截图只用于一张成品。队列海报展示同一界面的两个不同局部，明确分开标注当前与后续任务。用于候选筛选的历史原图和联系表不作为帖子图片发布。
