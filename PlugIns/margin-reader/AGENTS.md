# Margin Reader development rules

This plugin follows the parent Agents Company repository's development rules and version-control policy; do not assume a separate Git repository. Limit all edits to this plugin folder. Never stage, commit, reset, clean, stash or edit other parts of the parent repository as part of plugin work. Preserve user workspaces and their documents. Do not run model employees for reader tests.

Read the parent PLUGIN_SPEC.md and this plugin's API.md before changing the contract. Every persistent capability must be implemented in runtime.request and declared in scripts/contracts.cjs. UI code may only call public methods and render their results; no business data in browser storage or private host IPC. schema.json, manifest and API.md are generated by the scripts; update the generator rather than drifting generated files.

All business paths are scoped to the exact workspace. Keep traversal, symbolic/hard link and protected metadata checks. Employee CLI must use its assigned mailbox/credential and must never fall back to another workspace or global credentials. Preserve originals. File deletion goes to recoverable trash; never add implicit permanent deletion. Outline mutations require an explicit version check; never silently retry a stale edit over a newer value.

The MOBI/KF8 compatibility adapters intentionally target pinned @lingo-reader/mobi-parser 0.4.6. Check actual MOBI and AZW3 files, original TOC locators and Unicode byte offsets before upgrading that parser. Do not remove the compatibility tests merely to make an upgrade pass.

Run npm run test:agent-acceptance after changes: it builds the plugin and runs core, host, real employee-launcher, browser and hidden homepage/native-window tests. The existing npm test, npm run build:plugin, npm run test:ui and npm run test:host remain available separately. Employee transport/synchronization changes must also pass npm run test:employee and npm run test:team-ui. Tests use the host's protocol fixture, never a real model turn. npm run test:live explicitly downloads temporary public-domain fixtures and checks public URL import; it is separate from offline tests. UI/host tests use isolated temporary workspaces, no model calls and no visible windows. Reports and screenshots go into ignored artifacts/. Never commit user documents, runtime caches, credentials, downloaded books or node_modules.

Do not watch .agents-company mailbox files as business changes: publishing events.json must not feed back into runtime.subscribe. Only committed .margin-reader/state.json and user files should trigger external-library refreshes.

Build output defaults to dist-plugin/. --out may target a new plugin package directory but must never target the source root or its ancestors. The host's shared plugin bar currently does not support custom image icons; the independent SVG is used inside the reader and as its favicon. Do not modify the host protocol just to change this.

After map/list rendering, annotation, text-offset or toolbar changes, run `npm run test:deep-audit`. It retains failed runs and lists skipped/untested cases separately. Do not remove a failing assertion merely to make an old interaction test pass: exercise the current public contract and retain coverage of direct-card versus automatically bound map input.

The complete graph remains in the model. UI viewport mounting and 100-card list pages must never truncate exports, source targeting, keyboard focus or bulk operations. Validate actual card body/footer geometry, not only the existence of DOM nodes. Never rebuild PDF pages beneath a held or unresolved ink draft. Synthetic text-only benchmarks do not establish heavy-image, hardware or cross-platform parity.
