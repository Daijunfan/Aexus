# 原位交互、自定义主题与可恢复备份

日期：2026-10-01。修改范围：`PlugIns/margin-reader`。本轮延续 Telegram 风格的层次、配色与操作反馈，同时补齐真实的本地业务流程。最终通过数量和源码指纹以 `interaction-results.json` 为准；本文不将局部功能与全部 MarginNote 本地能力等同。

## 1. 阅读时直接编辑卡片

选中卡片后按 F2，或点击工具栏“详情”，打开非模态编辑面板。阅读区域仍可见，标题、正文、笔记、颜色和标签在同一个面板中处理。保存使用公开 `study.card.update` 和学习集版本；Cmd/Ctrl Enter 与保存按钮一致。摘录的显示文字保存在 `editedText`，不可变原文引用、PNG 和 PDF 不改写。

并发编辑使用明确的冲突反馈。另一端修改学习集后，本地草稿保留；面板显示最新内容供比较，重新载入或关闭前需要明确放弃。即使卡片加载请求已发出，用户在返回前继续输入，过期结果也不会替换输入。宿主关闭检查与切换文档会拒绝未保存修改。实时引用的标题和正文在原卡片中编辑，避免产生无法显示的本地副本。

草稿目前保存在窗口内存，不提供断电或浏览器崩溃后的草稿恢复。保存、并发拒绝、重载、放弃、来源跳转和撤销各自独立验收，不以一个“保存成功”的提示代替数据检查。

## 2. 工具分层与可搜索操作

Cmd/Ctrl K 打开工具检索，支持中文与英文关键词、类别、方向键和回车。没有文档、没有选择卡片或当前动作被禁用时，显示具体原因；不会借搜索入口绕过权限或版本约束。执行复用原有按钮与公开 Core 操作，不再维护另一套业务实现。

学习工具区新增笔记、整理、链接、手写和复习分类。“全部”恢复所有原有入口，选定类别不会删除或重新创建工具。阅读工具栏压缩为单行，常用字号、搜索、重载、导出优先；剩余工具可横向滚动，键盘焦点自动进入可见位置。工具栏高度与原文留出的空间按实际几何检查。

## 3. 原页创建文本框

在学习集中打开 PDF 后，点击“文本框”，再点击原页，或在空白处右击“在此处创建文本框”。拖入纯文本会预填正文并进入确认步骤。确认之前不生成卡片；取消、Escape 和无效输入保留原始文库。保存复用 `study.note.place`。

布局使用原始页坐标。局部折叠后点击的压缩显示位置会映射回原页，文本框中的 Markdown 与公式继续使用既有渲染。原文标注的右键菜单优先，仍可取消标注；文本框入口不会抢占标注操作。当前直接创建入口要求 PDF 已属于当前学习集，不宣称独立文档的所有原版创建手势都已补齐。真实桌面拖放来源由浏览器 DataTransfer 测试覆盖，不能据此推出所有第三方原生应用的拖放行为均相同。

## 4. 自定义主题和本地分享

八套预设配色继续保留，增加自定义强调色、柔光色和背景浓度。输入为严格的 `#RRGGBB`；空值恢复预设，零浓度可关闭装饰。文字和主按钮颜色由确定性算法调整到足够的对比度，原文、图片与标注仍保持独立。正文与脑图世界坐标不应用装饰性变换；系统减少动态优先。

主题文件为 `margin-reader.theme/v1` JSON，仅含 schema、title 和 settings。单份上限 64 KiB；禁止任意 CSS、脚本、URL、字体及其它资产。导入先通过 Core 验证并预览，明确应用后才修改外观。导出也可使用当前预览而不切换已保存的主题，目标已存在时拒绝覆盖。

`appearance.get` 返回仅包含外观状态的指纹。修改、导入可以比较该指纹；另一端只调整页码或字号不会让外观失效，另一端改变外观则明确冲突。恶意主题和含非法外观字段的备份在应用或恢复前被拒绝。

## 5. 可暂停和重启续做的备份

“备份 / 版本 → 可暂停 / 重启续做的备份”创建独立任务。准备阶段冻结元数据、文件清单及原件版本；每批通过公开 API 推进，暂停和关闭会停止发送后续批次。没有持续运行的隐藏备份线程。

复制以 4 MiB 分块提交。当前文件首次先使用原生 SHA-256 读取整文件，最终校验也按完整文件推进；这些阶段的耗时依文件大小，不能将 `maxChunks` 误认为硬时间上限。中断复制从已提交块继续，中断整文件哈希或校验重做当前文件。加密检查点保存的是加密内容，重新打开需要再次输入口令。

元数据固定为准备时版本，后来新增的文件和修改后的笔记不加入本次快照。已经复制完整的原件独立保存；尚未复制完的原件版本变化时拒绝混合快照。对旧的任务版本重复推进会返回冲突，同一任务的并发推进由独占锁隔离。

所有文件完整性通过后才发布标准 `margin-reader.backup/v2` 目录包，继续使用既有检查和恢复接口。重复提交同一已完成发布可恢复原结果；发布后回执写入失败会明确要求读取同一 UUID，不能盲目创建重复任务。目标存在时，包括空文件夹，也不会覆盖。显式清理检查点只移除私有临时副本和进度，不删除原件和已经发布的备份。

保留的故障边界：进程异常退出后安全锁最长约 120 秒到期。若在“已预留空目标目录、尚未 rename”的极短窗口结束进程，可能留下空目录；插件保留检查点并返回 ALREADY_EXISTS，要求用户核对后处理，不会自动删除来源不明的目录。真实断电、外置盘热拔插及其它文件系统仍需单独测试。

## 6. 员工操作与验收方法

新增四个外观接口和六个备份任务接口，均通过宿主授予的同一个 workspace 运行。员工不需要私有 GUI 通道；文件导出、检查、导入、任务创建、读进度、推进、发布与清理都有明确契约。含口令请求应从标准输入传入，宿主 mailbox 的临时请求文件仍按宿主的标准权限与生命周期管理。

核心测试检查数据字节、ID、原件哈希、并发版本、拒绝路径、磁盘满、损坏块、部分写入和发布回执恢复。浏览器测试使用实际点击、键盘和受控异步延迟。断进程测试仅结束此测试自身创建的隔离 worker，不结束用户应用或其它进程；它不等于物理断电。

复现入口：

```sh
npm run test:deep-audit
npm run test:agent-acceptance
npm run test:interaction
npm run test:backup-jobs
npm run test:backup-jobs-ui
npm run test:backup-crash
npm run test:backup-job-large
```

`test:backup-crash` 可能等待约两分钟使真实遗留锁到期。`test:backup-job-large` 生成约 1.125 GiB 临时数据，需要至少 5 GiB 可用空间。两者只使用测试新建的临时文库，完成后清理。

## 7. 仍需完成的全项目目标

原版 `.marginpkg` 迁移、同一文库多个独立原生窗口、操作系统级深链、Obsidian 双向同步、完整物理笔与掌拒体验仍不能计为已实现。单库大规模图片/笔迹/长历史的长期驻留、所有第三方应用版本及其它操作系统也没有因合成测试而获得通过结论。完整目标和逐手册记录继续保留在 `MARGINNOTE_COVERAGE.md` 与 `marginnote-requirements.json`。
