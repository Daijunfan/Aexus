# Margin Reader：功能、交互、性能与工程质量深度审计

增量提示：本报告的计数与性能表保存 228 命令阶段的实测。后续已增加 GB 级流式备份、正文词典和子脑图字典范围；新增实测、最终回归及尚未关闭的问题见 [LOCAL_HARDENING.md](LOCAL_HARDENING.md)。原版迁移、多窗口和真实设备等缺口没有因此关闭。

日期：2026-09-30。对象：Agents Company 内的 `PlugIns/margin-reader`，0.7.0，228 个公开命令。范围：保留全部本地能力目标，排除 OCR、联网备份及依赖联网服务的部分。原版文档以 MarginNote 4 官方手册为基准；不同版本/付费档位的营销名称不作为已实现证明。

## 1. 结论与证据边界

当前插件已具备阅读、摘录、脑图、复习、页面编辑、本地导出及员工 CLI 的大部分基础结构。但功能名称接近、API 存在、单元测试通过，都不足以说明实际体验或商业产品兼容性已经达标。本轮在 264 项原有核心测试全部通过的情况下，仍发现万张卡片界面阻塞、卡片盒正文严重裁切、工具区挤占阅读空间、字典搜索静默遗漏、Unicode 定位偏移和界面/员工测试漏项。

这些具体问题已修复并增加回归；仍有原版数据迁移、同库独立多窗口、操作系统深链与 Obsidian 联动等实质缺口。此报告不把 77 篇手册整体标为完成，不把未测环境标为通过，也不提供未经测量的“功能完成百分比”。最终测试数量、失败/跳过项及日志位置由 [本轮结果](deep-audit-results.json) 给出。

审计同时使用源码检查、公开 CLI、真实员工凭据/启动器、无头浏览器、隐藏 Electron 窗口、截图、元素实际几何和合成压力数据。手册清单见 [MARGINNOTE_COVERAGE.md](MARGINNOTE_COVERAGE.md) 与 [marginnote-requirements.json](marginnote-requirements.json)。既有 77 篇清单保留，本轮重新在线核对了联动、手写、关键词、多窗口、迁移和导出等关键章节。

## 2. 性能：发现、修改与可复现数据

同一台 macOS arm64 / Apple M5 Pro，Node 26.5.0，已有 Chromium headless shell。负载为 10,000 张普通文字卡片、200 个根分支、每分支 50 张，约 5.83 MB 状态。基线一次，修改后三次；每次使用独立临时文库。以下比较只针对本插件修改前后，没有测量 MarginNote 的耗时。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 首次界面就绪 | 89,200.24 ms | 242.51 / 229.25 / 236.97 ms |
| 切换卡片盒 | 6,758.13 ms | 235.60 / 174.31 / 239.97 ms |
| 脑图页面 DOM 元素 | 140,574 | 636 |
| 卡片盒页面 DOM 元素 | 260,574 | 1,787 |
| 初始实际挂载脑图卡片 | 10,000 | 4，随滚动加载其余卡片 |
| 卡片盒实际挂载卡片 | 10,000，另有隐藏脑图 | 每页 100，隐藏脑图不挂载 |
| 观测到的最大浏览器长任务 | 88,673 ms | 三次均未观测到 ≥50 ms 长任务 |

修改后就绪中位数 236.97 ms，卡片盒中位数 235.60 ms。基线过程中一次系统采样看到渲染进程约 2.53 GiB RSS 和一个 CPU 核心持续忙碌；这属于观测点，不能称为精确峰值。JavaScript 堆没有显示一致下降，不能用 DOM 降幅代替全部内存降幅。

### 2.1 根因与实现

原脑图一次性生成所有卡片、SVG 和手写层；卡片绑定逻辑在循环中反复全表查找、读布局，切换卡片盒后还保留隐藏脑图。新实现用空间索引按视口挂载，合并分支 SVG 路径，复用 ID 索引，跳过没有笔迹的空手写层。完整布局、卡片 ID、关系、导出和批量操作仍保留全部数据。

卡片盒及大纲使用 100 张一页，提供首页、上一页、直接页码、下一页、末页；来源定位会自动切换到目标所在页。测试明确访问第 100 页和末张卡片，验证 CLI 修改、筛选、返回脑图、键盘焦点与缩放，避免以静默截断换取性能。

PDF 原有画布预算为 7 页，但标注层此前仍可能遍历全部页面并在无关事件下销毁重建。本轮将标注挂载限制到实际渲染完成的页面，按页分组并缓存几何/内容键。120 页、每页一条标注的测试检查末页取消/恢复和不相关设置变动。

### 2.2 仍未解决的规模风险

状态仍由单一 `state.json` 承载，读取解析和修改保存涉及全库 JSON；写锁中还可能包含昂贵工作。普通文库中便于检查与备份，在大量笔迹、多文库、长历史和高频多员工写入下需要进一步测量。10,000 张文字卡片的成绩不能外推到 10,000 张高分辨率图片、极深层级、跨屏超大笔迹或长期内存稳定性。

后续应先建立 50 MB 以上元数据、图片/笔迹混合、并发写入、崩溃恢复和小时级驻留基准，再考虑索引、增量日志或 SQLite。任何存储迁移都要保留原文件备份、可回退版本和跨版本恢复测试。

## 3. 界面：可见不等于可用

### 3.1 卡片盒内容被压成细线：已修复

原 CSS 网格将所有隐式行压进固定高度的滚动容器，卡片自身高度小于正文及脚注高度，内容被裁切。早先只检查 DOM 数量或 `visible` 的用例无法发现。现在使用按内容确定网格行高、卡片最小高度，并断言正文实际高度、脚注位于卡片内、最后一张卡片可滚动到达。

### 3.2 工具栏占据过多空间：已改善

常用视图、编辑和搜索置于首层；整理、连接、手写、复习等既有工具移入可滚动、可展开工具区。没有删除功能或另建私有状态。键盘焦点会进入可视范围。1520×1000、1024×768、780×768 通过卡片正文/脚注、滚动与工具打开检查；在小窗口仍保留至少 180 px 主内容区域。

这仍是保留现有工作流的重排，尚未完成商业级的整套信息架构、图标语言、微交互、全局可访问性和每种语言输入法验证。菜单数量与弹窗层级仍多，下一步应按当前场景显示最少必要动作，并用真实任务完成时间和误操作率判断改进。

### 3.3 复习与书写生命周期

移动工具栏容器后，复习界面的旧直接子级 CSS 失效；已修复选择器并跑回归。脑图新手写入口缺少暂停识别的矩形/涂抹反馈，已恢复提示，保留一次提交、冲突拒绝和明确重试。页面加载增加 `aria-busy` 和书写提示。手写保存中或冲突草稿未处理时，页面重排会等待，保存/放弃后继续。

测试还区分两类行为：脑图上自动绑定卡片的笔迹采用脑图世界坐标/笔宽；文档内直接编辑笔记采用卡片局部坐标/笔宽。分别验证，避免用过时接口预期误判或删掉真实覆盖。

## 5. 本轮新增的检索与词典修复

旧词典按标题长度只取前 1,000 个词，导致较短或排序靠后的词永久失联。现在以字面量前缀树检查所有候选；同一渲染复用 DOM 和字典上下文。仍为交互安全限制单卡合计 200 处自动链接，但明确返回 `linkStatus` 并在界面提示，保留全部文字和检索入口。

关键词支持英文/中文分号分隔别名，同一张卡片重复别名不会变成虚假的多个目标；不同卡片同名仍保留候选。此行为对照官方标题链接章节。[1]

另一个独立错误是 Unicode 小写展开，例如 `İ` 变成多个 UTF-16 单元，旧匹配位置会偏移。现在词典与检索都映射回原始字符串。流式文档搜索返回段落内部准确 `textOffset`，长段落内可跳到真正命中位置；布尔全库搜索不会把 `NOT` 分支或仅标题条件当作正文定位目标。

## 6. 数据安全和规模上限

现有实现的重要优点是：工作区限制、原件不覆盖、软硬链接检查、不可变图片资源、版本冲突、原子写入与可恢复删除。测试继续覆盖源文件哈希、恢复、错误权限、损坏输入、旧映射修复和员工撤权。没有把多文件保存描述成断电场景的完整文件系统事务。

本轮初始全库备份有 256 MiB 总数据/输出上限及 20,000 文件上限，并使用内存 ZIP；普通文件导入上限可大于它。真实大文库可能出现“文件能导入但整库备份超限”。本轮未通过简单放大内存上限掩盖该问题。后续增量已实现流式分块、逐文件哈希、空间预估、失败回滚及实际 GB 级恢复测试，详见 LOCAL_HARDENING.md；中断续传仍未完成。

撤销历史受 30 步/8 MiB 预算约束，不能替代长期版本备份；命名版本也需磁盘配额/删除规则。多个员工高频写入的大文库、磁盘满、外置盘意外拔除、长时间崩溃重启还需要专门压力与故障注入。

## 7. 原版迁移、窗口与外部应用：保留实质缺口

官方记录了从 MarginNote 3 备份迁移和 `.marginpkg` 学习集导入。[2] 本插件自有 `.mrpkg` 的导出恢复不能证明能够读取原版包。验收应使用有授权的非敏感真实原版样例，逐项核对文档、卡片、图片、笔迹、关系和复习数据，缺失必须明确列报。

官方同机多窗口要求的是独立视图的协同操作。[3] 当前宿主对相同插件/作用范围通常复用窗口，而业务选择与阅读位置也包含共享状态。需要在授权的宿主扩展点与插件中明确区分共享内容和视图会话，不能靠复制数据库伪造多窗口。依照本任务边界，本轮没有修改宿主。

插件内部解析 `margin-reader://` 已有入口，但外部应用唤起、定位并复用正确工作区需要真实操作系统链路。Obsidian 导出文件和存在内部 URI 都不能证明官方联动流程已经对齐；真正的增量同步还需要冲突策略、删除传播、稳定 ID 和原文反向定位。[4]

## 8. 测试策略与失败记录

回归不只统计断言数量。本轮新增 10,000 卡片压力、120 页标注窗口化、原始 UTF-16 搜索、完整词典/分号别名、卡片实际几何、响应式工具区和缩放/草稿生命周期检查。修复过程中保留了失败日志；没有删除出错用例或把退出码非零标记为通过。

部分旧 UI 测试在新手写接口下期待旧行为，已改为验证新的公开契约，并补上原先对应的“直接笔记”操作。另有两个测试在改变窗口尺寸后用旧坐标点击正在重排的 PDF：增加可观测的就绪/稳定条件，同时在产品中补齐加载提示和未保存笔迹重排保护。时间等待仅用于验证稳定性或实际隐退/长按，不代替业务结果断言。

完整命令：`npm run test:deep-audit`。单项：`npm run test:large-map`、`npm run test:annotations`、`npm run test:performance`。使用已安装浏览器时可传 `PLAYWRIGHT_EXECUTABLE_PATH`。所有动态资料位于隔离临时文库，无收费模型调用；截图和原始日志位于 `artifacts/deep-audit-20260930T140922Z/` 及测试记录指出的子目录。

测试环境只有本机 macOS arm64。Windows、Linux、真实笔/触摸/掌拒、VoiceOver、外置卷热拔插、长时间驻留以及全部第三方应用版本没有验收。端到端测试使用协议 fixture；没有让真实模型员工执行任务。

## 9. 下一阶段的验收门槛

第一优先：原版包迁移、GB 级分卷备份恢复、同库多视图、操作系统深链/Obsidian，均要有真实往返数据和冲突失败证据。第二优先：把文档词典、完整套索操控和复杂复习遮挡补到逐条手册语义；不能复用“支持链接/手写”的笼统结论。第三优先：Windows/Linux、实体笔/触摸、国际化输入及长期稳定性。

性能门槛应包含冷/热启动、连续快速操作的 p50/p95、峰值 RSS、长任务、图片/笔迹混合、并发保存与故障恢复；与商业软件速度比较需要同机、同文档、同操作的独立实验。当前只有自身前后对比数据。

## 10. 交付与复现

源码及构建仅在 Margin Reader 插件目录内。本轮不替换运行中的应用、不移动个人文库、不提交或清理 Git。`dist-plugin/` 是可安装的构建输出，不能据此声称用户当前应用已经加载该版本。原源码基线、范围哈希、性能样本和各轮失败/成功记录全部保留。
