# Margin Reader：员工全链路开发与验收

## 交付范围

本轮只修改 `PlugIns/margin-reader`，保留原有工作区、文档和仓库未提交修改。未修改宿主源码、父级依赖或父级构建目录，未替换正在运行的真实应用。版本仍为 0.7.0；新增接口参数保持向后兼容。

## 已完成的修复

1. **修复真实员工运行时的事件循环。** 原先宿主每次持久化 `.agents-company/.../events.json` 都会再次触发文库通知，持续重置界面的刷新计时器。现在忽略宿主通信、Git 和派生缓存，只监听提交后的阅读器状态和用户文件；实际外部编辑仍正常通知。
2. **打通 CLI 与可见界面。** CLI 返回指定文库文件夹、折叠/展开 PDF、明确重新解析文档时，当前窗口同步刷新；正文重解析保留文档 ID。员工原生窗口中的正文、目录、主题和导航已实际验证。
3. **加固员工传输。** 限定当前工作区和请求 ID，校验宿主存活、响应格式与请求对应关系；拒绝路径逃逸、符号链接通道和缺失凭据。员工宿主不可用时，不借用用户身份、不创建另一个独立文库。请求提交后断线或超时明确报告可能已完成，不自动重发写操作。
4. **补齐完整检索与命令发现。** `help METHOD`、`schema METHOD` 返回单个命令的完整参数，无需运行中的宿主。学习卡片检索覆盖标签，支持 `limit`、`offset`、`nextOffset`，不再默默截断 500 条之后的结果；以 507 张卡片验证完整分页、去重结果及只读行为。
5. **防止规范漂移。** 构建检查确认生成的 schema 与命令定义一致；同步更新 API、使用说明和插件开发规则，并补充真实员工与主页面回归测试。

## 作用范围与部署边界

员工可以使用其**获授权目录内的全部已声明功能**，不能因此取得 Team 根目录、同级员工或其他 Team 的数据；这符合宿主的授权模型。查看该员工的文档和学习集，应使用：

```sh
agents plugin open margin-reader --employee EMPLOYEE_ID
```

默认侧栏文库、Team 根目录和员工目录不是同一份数据库。实际路径由宿主提供，不应自行拼接或假定固定目录。

本轮生成的插件包位于 `dist-plugin/`。它已在隔离宿主中安装和验收，但**未擅自覆盖用户正在运行的应用或更换其已加载的插件实例**；日常应用需通过项目既定的插件安装/构建流程加载这一产物。

## 复现

在本插件目录执行：

```sh
npm run test:agent-acceptance
```

流程依次构建插件并执行核心、标准宿主、真实员工、浏览器、主页面/原生窗口测试。单项入口为 `npm test`、`npm run test:host`、`npm run test:employee`、`npm run test:ui`、`npm run test:team-ui`。

验证环境为 macOS arm64、Node.js v26.5.0。浏览器缓存不在测试进程 HOME 下时，给 `PLAYWRIGHT_EXECUTABLE_PATH` 设置已有 Chromium/headless-shell 的可执行文件路径。本轮使用已有浏览器，不下载或修改用户日常浏览器配置。

宿主测试使用独立临时 HOME、应用状态和工作区，使用本地协议 fixture，不调用真实模型。Electron 窗口保持隐藏，验证零模型调用和零未捕获浏览器错误；不创建真实用户 Team。隔离环境在结束后清理。
