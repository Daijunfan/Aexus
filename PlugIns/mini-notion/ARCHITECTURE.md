# 本地双端架构

目标：GUI 与 CLI/API 共用本地操作内核和数据，不复制两套业务逻辑。

1.11 的 Agent 接入位于 `src/backend/agent/`：`codex.ts` 使用官方 App Server，`claude.ts` 使用官方 Agent SDK，`runtime.ts` 管理会话、流式事件、交互请求与记录。`environment.ts` 为每个 Workspace 提供物理写入沙箱和固定身份的本地 API gateway；请求身份由连接注入，不能通过清除 token 绕过。主服务的无范围 socket 不向 Agent 进程开放。

引擎的配置、临时文件和本机会话存放在空间内的 `.mininotion-runtime/`。原有插件通过 APFS copy-on-write 副本提供给空间，避免修改全局安装。该私有目录不出现在文件面板或普通文件备份中。`space.sync` 将其他物理文件发现到页面文件记录。Claude 默认使用 SDK 配套二进制；`claudeControl.ts` 透传 SDK 流并复用公开控制请求协议，补充 Query 未包装的原生方法。队列与页面/块引用由服务验证和持久化，UI 与 CLI 使用同一分发器。

`src/core/overview.ts` 为综合页面和 CLI 返回同一投影；`src/core/agentCommands.ts` 为斜杠菜单和 CLI 提供同一命令目录。视图字段由 `viewSchema.ts` 描述并校验，删除可选配置使用 `view.update --unset`。

引擎控制请求不占用单写入队列等待用户回答；页面和会话状态写入仍经过队列。运行连接绑定不可变的 `(pageId, conversationId)`；状态、消息、队列和审批均带会话身份，后台事件写入该会话的快照，不会跟随当前标签。`conversations.ts` 负责标签切换与历史日志兼容；当前会话保留在 `space.agent`，其他会话快照保留在 `agent.sessions`。每个连接使用独立的 `bin/<conversationId>/mininotion` 和 gateway，物理目录边界仍为同一个 Workspace。

- `src/core/`：可序列化命令、命令目录、输入校验、页面/块/数据库等操作，以及并发合并。复用现有 `model.ts`、数据库查询和公式实现。
- `src/backend/`：本地数据服务，独占工作空间写入，通过用户私有的 Unix socket 提供 JSON RPC 和事件流。GUI 关闭后 CLI 仍可工作，不开放公网端口。macOS 后台使用应用自带的独立 Helper 运行时，避免与主窗口共用应用标识。
- `src/cli/`：参数解析、文本/JSON 输出、文件输入、命令发现。CLI 调用同一个服务，不直接改工作空间文件。
- `electron/`：窗口、原生菜单和文件对话框；将 renderer 的操作转给本地服务，并广播外部变更。
- `src/store.tsx`：界面乐观更新、服务确认状态与未确认操作。服务变更重新应用未确认操作，保护正在输入的内容。

数据安全要求：

1. 一个工作空间只有一个服务写入。所有修改依次提交并保留现有原子写入和备份。
2. GUI 发送修改过的页面/字段，不以整份旧工作空间覆盖 CLI 的修改。
3. 无冲突修改合并；同一内容产生冲突时保留草稿，明确返回冲突信息。
4. 所有块具备稳定 ID，命令行可精确定位，移动/复制后引用仍可解释。
5. 文件导出、完整备份和渲染操作不能通过弹出对话框阻塞 CLI。
6. 命令目录是 CLI/API 的可发现契约；新增 GUI 功能必须同步添加命令和双端测试。

1.2 已安装并验证内置运行时及数据迁移。1.3 在同一内核中加入模板、子项目、依赖与日期范围；升级只在旧 GUI 退出后自动切换后台服务，避免新界面连接旧内核。

页面历史每 5 分钟保留版本；独立的 `changes.json` 保留 150 项可撤销的数据操作，连续 GUI 输入适度合并。PDF 通过独立 Electron 进程使用真实桌面渲染器和只读快照。应用关闭前会等待待提交编辑，未确认草稿保存在图形端本地存储并在启动后重新提交。

- 数据库模板也是页面，以 `templateFor` 绑定数据库，普通查询隐藏模板及其后代。实例化复用页面树复制与引用重映射。
- 数据库记录仍以 `parentId` 指向所属数据库；`subItemOf` 表示记录间层级，`blockedBy` 表示前置依赖。相关系统关联属性从这些字段计算，避免重复维护两份关系。
- 依赖图在提交前校验，自动排期在唯一写入服务中按拓扑顺序传播。受影响记录一起提交、一起保留操作历史；备份恢复和显式撤销不会再次触发自动排期。
- 视图展示、日历区间布局、日期移动和 CLI 投影共享纯函数。属性/模板删除会清理关联视图中的相应配置。

- 评论存储在页面的讨论数组中，消息、讨论和正文块有独立 ID。同步内容使用隐藏页面存储，引用块仅持有 `sourceId`，编辑、评论、历史和并发合并复用同一页面内核。同步引用在提交前校验循环；导出和搜索按引用解析正文。

- `src/scheduling/` 保存循环、提醒与收件箱的共享规则。循环和提醒定义附着于页面；运行水位、投递标记与收件箱在工作空间根字段中持久化。后台计时器与 CLI 检查都进入同一请求队列，完成后才广播通知。
- 调度水位不进入页面撤销记录。模板生成复用原有复制与引用重映射，提醒跟随当前日期计算；原始模板不投递通知，副本有独立提醒 ID。原生通知适配器位于桌面主进程，测试模式记录事件并提供点击模拟，不修改系统通知或 URL 处理器设置。

## 空间与 Agent

- 空间、主页面、Agent 以同一个主页面 ID 固定关联。规范化负责旧数据迁移；命令层阻止换绑，复制空间创建独立文件和新会话。
- `src/backend/agent/` 使用 Codex App Server 与 Claude Agent SDK 的常驻会话。固定启动器绑定当前构建和空间 gateway；外层 macOS sandbox-exec 约束引擎及所有子进程的物理写入。Codex 声明 externalSandbox，避免重复嵌套系统沙箱。
- Agent 命令先在空间投影上执行，再复用公共差异合并接口提交到唯一写入方；主页面、子页面、视图与文件共用原来的业务命令。Professional CLI 保留完整管理功能。运行时内部状态写入不开放为公共命令。
- 上传端点和 `space.upload` 共用落盘与登记链路。空间 URL 含主页面命名空间；聊天保存文件快照和文件 ID，主页面与聊天按文件 ID 打开同一个文件预览。完整备份携带根目录／文件夹文件与会话日志。
- 引擎的标准输出按 UTF-8 JSONL 解析，保留未换行尾包。会话、工具调用、完成、失败分别处理；Codex 的可恢复 item 提示不等同于回合失败。工具 ID 映射在运行时维护，避免同一输出包中的开始与结束早于持久化确认而产生重复记录。
- UI 使用共享状态和完整会话日志渲染消息、Markdown、附件与工具结果。拖动位置属于 `settings`，CLI 可读写；工作期间生成的页面和文件通过服务事件同步。
- 接入参数核对了本机 CLI 帮助及 [Codex 配置文档](https://learn.chatgpt.com/docs/config-file/config-reference)。真实模型验收与确定性协议测试分开记录，见 [AGENT_ACCEPTANCE.md](AGENT_ACCEPTANCE.md)。


Workspace 外层沙箱还拒绝 Apple Events、Launch Services 打开请求和相关 Mach 服务，并把信号与调试任务端口限制为 same-sandbox，防止通过已有应用或外部进程委托写入。用户主动打开登录链接由宿主 UI 执行；引擎不能借系统 open 委托到沙箱外应用。
