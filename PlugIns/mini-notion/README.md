一个以 Notion 页面和视图为基础的本地多 Agent 操作系统，面向 macOS。每个空间固定拥有一个主页面和一个 Agent，子页面与数据库视图在空间内组织工作。页面、附件和会话记录保存在本机；Agent 使用官方 Claude Agent SDK 配套引擎或本机 Codex，并继承已有服务配置。GUI 与 CLI 共用一个自动启动的本地数据服务，UI 能力是 CLI/API 的子集。

## 运行

1.14 增加文件夹渲染模式和 Agents Company 插件包。使用 `--workspace /absolute/folder`
将现有工作文件夹作为数据源；普通 Markdown/文本、CSV、图片和 PDF 直接映射为页面，
结构化页面、数据库和记录保存为 `Documents/*.mininotion.json`。CLI、独立窗口及
宿主中的嵌入界面共享该文件夹的同一个后端服务。

```sh
npm run build
node dist-cli/cli.cjs --workspace /absolute/folder fs list
npm start -- --workspace /absolute/folder
npm run build:plugin -- --out ../Agents-company/plugins/mininotion
```

文件夹模式不读取独立 App 的个人数据，也不启动自身 Agent。在 Agents Company
中由 Team 员工使用注入的 CLI/API；独立原生数据模式保持原有功能。
详见 [CLI 文件夹模式](CLI.md#文件夹模式与宿主插件) 和插件包内生成的 `API.md`。

开发环境：macOS、Node.js 24+、npm。当前构建目标为 Apple Silicon（arm64）。

```sh
npm install
npm run dev
```

构建与启动独立桌面窗口：

```sh
npm run build
npm start
```

生成 `.app`、DMG 安装包和 ZIP：

```sh
npm run package
```

打包输出在 `release.noindex/`，暂存应用位于 `release.noindex/mac-arm64/Mini Notion.app`；此目录不参与 Spotlight 搜索。正式安装统一保留在 `~/Applications/Mini Notion.app`，安装后移除暂存应用，避免出现重复入口。应用使用本地临时签名，未使用 Apple Developer ID 签名或公证。

## 使用

- **空间**：一个顶层页面就是一个空间，两者严格一一对应。侧栏「新建空间」选择 Agent 引擎（Claude Code 或 Codex）。空间拥有独立的文件目录：可上传文件和图片、新建任意层级的文件夹、拖动整理、在访达中打开；不同空间的文件彼此隔离。旧笔记的顶层页面会自动成为空间。见 [CLI.md](CLI.md#空间与-agent)。
- **Agent**：每个空间绑定一个 Agent，用自然语言操作这个空间。主页面及其子页面右上角都可打开同一个 Agent，默认停靠在右侧，也可切换为可拖动浮窗。支持多文件、多图片、文本混合或纯附件，通过箭头或 Enter 发送；拖入与粘贴图片也可用。附件先保存到空间，正文支持 Markdown 与页面／文件链接，完整工具输入输出可折叠查看。Agent 通过 Mini Notion 的命令行接口改动页面，所有写入都限定在该空间内；会话可以续接，重启后恢复。引擎未安装时会明确提示。
- **页面**：侧栏添加、嵌套、展开、重命名、收藏、复制、拖动排序和移动层级。顶部支持面包屑与前进后退；删除的页面可从回收站恢复。
- **写作**：块编辑、`/` 菜单、悬浮格式工具栏、块拖动、多栏排版、标题、待办、列表、折叠、引用、提示、代码高亮、表格、分割线、图片、视频、音频和文件。输入 `@` 引用页面，输入 `/页面` 创建子页面。输入 `/两列`、`/三列` 创建分栏，也可拖动块到另一块的侧面。
- **评论**：页面讨论、选中文字/块批注、回复、编辑、表情、解决/重新打开与删除恢复。署名在设置中修改，评论保存在本地。`⌘⇧M` 评论当前编辑器的选区。
- **同步块**：输入 `/同步块` 或在块菜单中转换现有内容；可在所有引用处直接编辑，复制并同步到其他页面、查看引用、取消单处或全部同步。正文和评论存储在共享内容中，支持 CLI 修改。
- **页面外观**：表情图标、内置或上传封面、封面位置、三种字体、小号文本、全宽、锁定、浅色/深色/跟随系统。
- **数据库**：表格、看板、计划、时间线、日历、画廊、列表、图表、动态和表单视图；21 种属性，包括状态、人员、文件、邮箱、电话、系统时间/作者、唯一编号，以及文本、数字、单选、多选、日期、复选框、链接、关联、汇总、公式和按钮。支持增删属性、筛选、排序、看板/日历拖拽，记录可侧边预览或作为完整页面打开。汇总可对关联记录计数、求和、平均值、极值或显示原始值。
- **状态与选项**：三个状态分组、默认状态、选项颜色、重命名和排序；计划的完成判断覆盖整个完成组。选项重命名会同步已有记录、视图条件及按钮/自动化中的字面值。
- **人员与文件**：本地人员名片、多人分配或单人限制；附件上传/拖入、网页链接、预览、重命名、排序、下载和移除。文件进入本地附件库，完整备份与 JSON 导入导出会携带文件。
- **系统属性**：库内自动编号与自定义前缀，删除或撤销后不复用编号；创建/编辑时间及作者不可手动改写。系统时间可用于日历、时间线和小时计划的只读展示。旧笔记没有的作者信息保持为空。
- **计划**：周计划、日计划、议程、按小时的日/周时间表、未排期、逾期、完成勾选、拖动排期、隐藏已完成；日期导航同步到 CLI。
- **小时排期**：双击空白时段创建事项，拖动移动时刻，拉伸结束时间；重叠事项并排，跨午夜事项分段显示。支持全天转换、完成勾选与键盘微调；视图时区独立保存，夏令时日显示实际 23/25 小时。
- **自定义视图**：添加、复制、重命名、删除、拖动排序；每个视图独立保存筛选、排序、分组、属性顺序和可见性。
- **公式**：支持 Notion 语法的条件、文本、数值、日期、列表、关联页面与变量表达式，提供结果预览、样式、链接和错误反馈。
- **内联与关联数据库**：在笔记中输入 `/内联数据库` 或 `/关联数据库`。关联视图共享原数据库记录，同时独立保存视图配置。
- **搜索**：`⌘K` / `⌘P` 搜索标题、正文和数据库属性；`⌘F` 查找当前正文。
- **模板**：保留内置日记、会议、项目、读书模板；数据库中可创建/编辑/复制自定义模板，包含正文、属性和子页面，可设为数据库或某个视图的默认模板。
- **循环模板**：数据库模板的「··· → 重复」设置日/周/月/年、自定义间隔、星期、月末/第几个星期、起止日期和时区；支持补最近一次、补全部或跳过，自动填写日期、标题和相对日期。侧栏「计划与提醒」可暂停、恢复、手动生成和查看记录。
- **提醒与收件箱**：页面顶部铃铛添加固定提醒，日期弹层设置跟随属性的提醒；支持提前/之后、日历天和分钟、已读/未读、归档/恢复、稍后提醒。设置中可开启 macOS 横幅；完整退出 GUI 后仍写入本地收件箱。
- **按钮**：输入 `/按钮`，或添加数据库「按钮」属性；支持多步修改属性、新建记录、筛选后批量修改、插入富文本、本地通知、提醒、变量公式与打开页面。可预览影响、配置执行前确认；按钮和其触发的自动化一起保存，页面修改可整体撤销。
- **自动化**：数据库顶部闪电按钮配置新增/属性变化、任一/全部条件、筛选或指定视图，以及周期触发。支持暂停、恢复、执行历史；复制数据库中的自动化默认暂停。详见 [CLI.md](CLI.md#按钮与数据库自动化)。
- **子项目**：通过数据库设置启用；表格、列表、时间线支持嵌套展开，卡片可显示子项目；父/子项目属性可用于公式与汇总。移动、复制、删除和恢复包含相应子项目。
- **依赖**：双向关联、时间线连线、鼠标连接或菜单选择；支持只在重叠时后移、保持任务间隔、不自动调整，以及避开周末。一次排期调整和它影响的后续任务可一起撤销。
- **日期与时间**：日期弹层支持日历选择、开始/结束、包含时间、时区和清空；表格、记录页、计划、表单和批量编辑使用同一编辑器。时区切换保持实际时刻，跨夏令时的日期移动保留本地钟表时间。
- **跨日安排**：日历显示跨日/跨周日期条，拖动保留持续时间与抓取位置。日历、计划和时间线可选择起止日期属性，CLI 使用相同日期查询与排期方法。
- **迁移**：导入 Markdown、HTML、纯文本、CSV 和页面 JSON；导出 Markdown、HTML、PDF、JSON 或数据库 CSV。Markdown 导入文件中引用的同目录附件会复制到本地附件库。
- **备份**：设置中导出/恢复 `.mininotion` 完整备份，包含全部页面、附件、模板、页面历史、操作记录和冲突草稿。恢复前额外备份当前工作空间。

常用快捷键可在「帮助」中查看，macOS 原生菜单也显示对应快捷键。

## 本地数据

正式应用默认使用 `~/Library/Application Support/Mini Notion/`。实际路径可在「设置 → 数据与备份」查看并用 Finder 打开。

```text
workspace.json     页面、块、属性、层级、偏好、调度进度、收件箱与空间配置
attachments/       页面正文引用的本地图片和文件
spaces/            每个空间独立的文件目录（spaces/<页面 ID>/<文件夹 ID>/）
agents/            各空间的 Agent 会话记录（agents/<页面 ID>.jsonl）
history/           各页面的历史版本
changes.json       最近 150 项可撤销的数据操作
conflicts/         保留的并发编辑草稿
backups/           最近 30 天的工作空间快照
```

GUI 经受限 IPC 和 CLI 一起调用本地 Unix socket 服务。只有服务写入工作空间，先写临时文件并 fsync，再原子替换。图形端发送差异修改；不同字段/块的并发修改合并，同一内容冲突时保留草稿供两端处理。保存失败会在窗口顶部显示，并可重试；不会显示为保存成功。页面历史以 5 分钟为间隔保留编辑前的内容，每页最多 60 个版本。每日工作空间快照不重复复制附件，完整离线迁移请使用 `.mininotion` 备份。

打开 GUI 或运行 CLI 会启动本地后台，关闭 GUI 后后台仍运行；系统重启后需再次启动 GUI 或 CLI。休眠/关机期间的循环按补发策略处理，已记录的触发不会重复执行。macOS 横幅需要应用主进程运行并获得系统许可；关闭窗口可继续提醒，完全退出后仍保留收件箱，重新打开即可查看。

`MINI_NOTION_DATA_DIR` 可指定独立数据目录，自动测试使用临时目录，避免接触真实笔记。

浏览器开发预览 `npm run dev:web` 使用浏览器本地存储；正式使用请选择桌面应用，原生备份、Finder、PDF 和附件目录由桌面应用提供。

## 验证

```sh
npm test          # 页面树、回收站、CSV、原子存储、附件和损坏数据
npm run build    # TypeScript 与生产构建
npm run test:e2e # 真正启动 Electron，验证主操作流程与重启持久化
npm run test:agent:live # 使用本机真实引擎与模型，验证页面编辑、资料整理、多视图和图片理解
```

Agent 桌面验收默认在隐藏窗口运行；其他桌面测试可使用 `MINI_NOTION_BACKGROUND_TEST=1`，生命周期可见性测试仍需普通模式。验收范围、证据与复现方式见 [AGENT_ACCEPTANCE.md](AGENT_ACCEPTANCE.md)。

端到端测试的 PDF 内容检查使用 Poppler 的 `pdftotext`（macOS 可通过 `brew install poppler` 安装）。测试截图与导出的 PDF 位于 `test-results/`。

## 结构

```text
electron/           macOS 窗口、原生菜单、IPC、原子存储和 PDF 渲染
src/core/           公共命令、差异合并与双端状态同步
src/backend/        单写入服务、Unix socket、文件与操作记录
src/backend/agent/  Agent 引擎适配、提示词与进程生命周期
src/cli/            CLI 参数、结构化输出和标准输入输出 API
src/model.ts        页面树与工作空间操作
src/store.tsx       工作空间状态与保存
src/components/     编辑器、页面、侧栏、数据库与对话框
src/actions/        按钮与数据库自动化，纯动作执行及图形配置
src/scheduling/     循环模板、提醒、时间规则与收件箱
src/transfer.ts     导入/导出数据转换
tests/              数据逻辑与 Electron 端到端测试
```

编辑器复用 [BlockNote](https://www.blocknotejs.org/docs)，桌面层使用 [Electron](https://www.electronjs.org/docs/latest/)，页面与侧栏的交互参考 [Notion 官方使用文档](https://www.notion.com/help/navigate-with-the-sidebar)。这是独立实现的单机应用，与 Notion 公司无关联；不包含账号、云同步、在线协作、Notion AI 或外部服务集成。

项目采用 GPL-3.0，包含所使用的多栏编辑组件的开源许可证。可重建的应用源码随桌面包一起提供，位于 `Mini Notion.app/Contents/Resources/Source.zip`。
