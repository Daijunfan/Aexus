## 验证原则

- 对照真实功能行为逐项验收，不以代码行数或已有测试数量代替功能完整性。
- 新功能必须实际工作、可持久化、与现有页面及导入备份兼容。
- 主界面和每种视图均进行运行时视觉检查；不能只检查某一张初始页面。
- 旧版用户数据保留。升级先在隔离测试目录验证迁移，再更新已安装应用。
- 此清单保留功能差异供参考；后续扩展由实际使用需求决定。

## 1.7 验收补充

- 循环模板支持日/周/月/年、自定义间隔、星期、月末与第几个星期、结束日期、时区和三种补发策略。动态日期、标题及子项目日期基于现有模板复制实现。
- 本地单写入服务调度，生成页面和触发进度原子保存。进度独立于撤销记录，避免撤销后再次生成同一批；大量补发分批处理并返回剩余状态。
- 固定时间与日期属性提醒、提前/之后、分钟/日历天、收件箱、已读/未读、归档/恢复、稍后提醒均有 GUI 与 CLI/API。1.8 已增加自动化通知；评论/提及等活动来源仍待扩展。
- macOS 横幅为可选项，需系统授权；主进程运行时（包括关闭窗口后）可投递。完全退出后仍由后台写入收件箱；系统重启后当前需要启动 GUI/CLI，登录自启与更完整的系统通知整合继续推进。
- 完整备份保留调度与通知状态；复制/导入模板的循环默认关闭。删除日期属性会停用其提醒并清除循环的日期绑定。

- 1.7 同时补齐无窗口主进程的 CLI 打开/退出，以及升级时对旧主进程的保护；通知打开的页面会持久化导航状态，继续编辑不会跳回旧页面。

## 1.8 验收补充

- 文档按钮与数据库按钮属性共用动作内核，GUI 和 CLI/API 可配置、预览、执行及查看记录；动作支持插入富文本、修改属性、创建记录、筛选批量修改、本地通知、提醒、公式变量、打开页面和移入回收站。
- 数据库自动化支持新增/属性变化、任一/全部触发（约三秒内）、筛选/限定视图，以及周期调度。用户点击按钮可触发规则；规则自身或循环模板生成的数据不继续触发规则，避免连锁执行。行为参考 [Notion 按钮](https://www.notion.com/help/buttons)、[数据库按钮](https://www.notion.com/help/database-buttons)、[数据库自动化](https://www.notion.com/help/database-automations)。
- 动作逐步计算，失败保留步骤错误，不保存部分页面修改；自动触发失败会保留用户原始编辑。预览不落盘；有确认文字的按钮需要 GUI 确认或 CLI `--confirm`，可使用预期配置拒绝执行已改变的按钮。
- 定时规则复用时区与补发策略，进度与结果原子保存；复制规则默认暂停。删除触发/范围属性会暂停相关规则，动作中的失效筛选会报错，避免无意扩大修改范围。
- 编辑器收到后端内容更新时不重复回写，防止程序渲染产生虚假的撤销记录；富文本插入、CLI 实时同步与重启保留已覆盖桌面测试。
- 1.9 已补状态/人员/文件/唯一 ID 等属性；条件颜色、多窗口/标签页、丰富搜索等保留为可选方向。联网邮件、Slack/webhook 等动作不属于当前离线实现，未提供虚假入口。
